受託案件のフロントエンド実装を主に担当し、現在は自社AI SaaS「開発AIコア」の開発にも参加しています。要件定義に近いところから入って、設計・実装・運用まで一貫して担当することが多いです。会社は途中で Tavern から株式会社バクに社名変更しました。

## やったこと

- **コーポレートサイトのリプレイス**
  - 既存のペライチ／素のHTML+CSSのサイトをNext.jsに置き換え
  - 設計から実装まで担当
- **ロードサービス系の管理システム構築**
  - フロントエンドの設計から実装まで担当
  - OpenAPIスキーマからOrvalで型・クライアントを生成し、バックエンドとの結合をスムーズに
- **設計図のAIレビューシステム（AI検図SaaS）PoC**
  - フロントエンド全般を担当。検査セッションの作成からステータスのポーリング、結果表示までの一連のフローを実装
  - 画像クロップ（react-image-crop）、検図履歴・結果ページ、PDFダウンロード・印刷機能
  - LLMを組み込んだUIと、ユーザーが結果を確認しやすいレビュー画面を実装
- **「開発AIコア」（LLMで成果物を解析し指摘を生成するSaaS）の開発**
  - 招待・認証フローの刷新（メール送信 + 初期パスワード方式への作り直し）
  - 管理者向けメトリクス（組織別利用状況・週次クレジット集計）の実装、PostHog導入
  - OSV-Scannerで検出される脆弱性の継続的な修正・依存関係管理
  - 用語統一・重要度ラベルなどUI品質の改善

## 使った技術

- Next.js / React / TypeScript
- Prisma / PostgreSQL
- Orval
- GCP Cloud Run / AWS ECS / Terraform

## 学び・所感

- 受託の現場では、要件定義〜納品までのリードタイムが短い案件も多く、PoCスピード重視の進め方が身についた
- AIを組み込んだプロダクトは、毎回同じ出力が返ってこない前提でUIを設計する必要があり、そこが一番難しいと実感
- OSV-Scannerが検知する脆弱性を潰し続ける役目をやって、依存関係の管理は根性ではなく仕組みで回さないと破綻すると分かった
